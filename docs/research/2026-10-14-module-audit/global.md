## Findings

1. **Most of the GLOBAL desk is not live, and it never was. Measured and checked against the code.** 11 of the 16 desk modules answer from registers stored in the repository: `src/data/*.json` and `public/data/embedded_csv/*.json`. Those files have not changed since 2026-09-01, 2026-09-09 or 2026-09-14, and they are dated 2025, 2026-06, 2026-07, 2026-08 or 2026-09-07. Production marks them `served: live` only because nothing outside was fetched and nothing timed out. The `sourceUrls` in `source-registry.json` (Google News, GDELT, OFAC SDN, ReliefWeb, CelesTrak active, Wikidata, Pink Sheet, World Bank Projects) are **not what the code calls** for these modules. The "feed fix / API fix" work so far (F154, F156, F159, F164, F165) changed **speed, fallbacks and wording**. It did not connect any GLOBAL module to a new real source.
2. **Only five desk modules fetch an outside source on each request.** These are Satellite Infrastructure (Space Devs), World Constitutions (Constitute Project), Growth Indicators (World Bank), Global Trade (World Bank) and Geopolitics News Wire (GDELT, then BBC World). In production the first four are fast (45–184 ms warm) and return 12, 188, 20 and 20 rows. The live side panels inside four modules are healthy in production: Sanctions → OpenSanctions (18 lists, updated 2026-10-14), Global Aid → OCHA FTS (36 plans), Infra → World Bank projects (12) and Choke-Points → IMF PortWatch (28, 2026-10-11).
3. **No GLOBAL module shows 1 listing in production now.** I checked every desk module twice, plus the landing counts. The only one-row answer is off the desk: Transit returns a single status row ("Live data is taking longer than usual"). Counts on GLOBAL differ from earlier versions for three concrete reasons:
   - (a) On 2026-09-14, Open Fronts and Global Intelligence stopped running product-name news searches, which returned tens of unrelated articles. They now use registers of 88 and 10 rows (commits `8a99ab1` and `7aa2739`).
   - (b) On 2026-09-14, Transit and Conflicts were removed from the desk, and on 2026-09-04 Critical Minerals was folded into Energy (`3de99c2`, `ae2cd40`).
   - (c) Since F154 (`719a7eb`), when a live module misses the 4 s limit, the page falls back to a backup workbook of a **different dataset**. Satellite then shows 500 of 16,506 CelesTrak catalogue objects instead of 12 launches, and Growth and Trade show 500 of 17,490 World Bank series rows instead of 20 economies. The visible count can swing between 12/20 and 500 depending on how fast the source answers.
4. **Geopolitics News Wire is stale in production on every request. Measured.** It took 4.06 s both times and returned the backup F12: 38 stories, the newest dated 2026-09-10. Fetched directly from the owner's Mac, GDELT returned 429 after about 11 s. The code then waits 5 s, retries, and only after that tries BBC, so the live path can never fit inside 4 s. BBC World alone answers in 0.33 s, and a local pull got 27 stories dated today. The browser archive has no stored rows for this module (`geo_news_wire.json` is empty) and calls GDELT directly from the reader's browser. Fix: try BBC first or in parallel, put a short timeout on GDELT, and drop the 5 s retry inside a request.
5. **F156's "only four packs on the live function" does not hold. Measured.** `vercel.json` `includeFiles` does not list `F12_Geopolitics_News_Wire.xlsx`, yet production (deployment `11cc881`) served it: `links: /backup/geopolitics/F12_Geopolitics_News_Wire.xlsx`. Vercel's file tracing is probably bundling the whole `backup/` folder, which `server/backupFeed.mjs` reads with `path.join(__dirname,'..','backup')`. This is not verified against the deployment file list. It matters because `src/backupPacksDeploy.test.js` and the open-work note assume about 5 MB is shipped, not 82 MB.
6. **Many notes and registry entries are wrong.**
   - Energy says "Illustrative levels — swaps to EIA/Trading Economics live", but no live feed is wired.
   - Heads of State's registry entry says Wikidata. A Wikidata loader exists (`server/resourcesApi.mjs` `loadLeaders`), but the module uses the 44-profile pack. It serves 43 rows because `leadersFromPack` drops one "(see …)" entry.
   - Global Commodities shows illustrative prices. The World Bank Pink Sheet XLSX is reachable (0.5 s) but nothing parses it.
   - The registry `sourceStatus` says "Direct feed configured" for all 19 entries.
7. **The upstream sources themselves are not broken. Measured from the owner's Mac.**
   - Working: Space Devs 200 (472 upcoming launches; the code asks for 12), Constitute 200, World Bank 200 (one 38.9 s outlier) and BBC 200. OFAC SDN returns 200 after a 302 to S3 (8 s), and CelesTrak active returns 200 (9 s, 7 MB).
   - Refusing: GDELT 429 and ReliefWeb RSS 202 (a bot challenge with an empty body). Neither is used by a desk module except GDELT in the News Wire.
   - Not tested: GDELT from Vercel bom1. The production diagnostic text comes from the archive pass, not from a real GDELT call.
