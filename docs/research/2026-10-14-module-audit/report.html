Your questions

Why does Cabinet Decisions show 1 listing?

PIB's live feed works, but it only ever holds PIB's latest 20 press releases, about one day's worth. On most days 0 to 2 of those are Cabinet decisions; today it was 1 (IDBI Bank restructuring). Since 13 October the page shows Cabinet decisions only. Before that it listed all 20 releases from every ministry, which is why it looked fuller.

Two more things make it thin. The filter goes by the office PIB names on each release, and PIB files about 41% of Cabinet decisions under the line ministry, so real decisions are dropped. And the stored copy used when PIB is slow has 6 rows, of which only 1 is actually a Cabinet decision. Meanwhile a backup Excel file with 158 decisions (21 January to 19 August 2026) sits unused.

Fix: make the 158-decision register the stored copy and add live decisions on top so the list grows; decide whether a "Cabinet approves…" release filed under a ministry counts. Scheduled fetching (F160) then keeps every decision instead of only PIB's last 20.

Are we pulling the real sources?

For 58 of the 123 modules, yes: PIB, RBI, Google News, World Bank, Wikidata, Sansad, ESPN, TVmaze, Manifold and others. 46 modules have never had a live source; they show a stored register or snapshot, many dated September 2026 or earlier. The fixes this week changed speed, fallbacks and wording only; none connected a new source.

Is the admin API status screen the same thing, and are there 800 APIs?

It is the same: its Refresh calls exactly the route the module pages use, so nothing is being reinvented. But its "Live" labels mostly come from a hand-written list and a rule that marks any Google News link as live. It shows 130 of 138 sources as Live; on the live site about 71 actually return fresh live rows. A refresh does not change the labels on the live site, and results are kept only in the admin's own browser.

There is no 800-API figure in the code. The real inventory is 138 connectors, 246 source addresses and about 20 outside services actually called. The nearest number, about 817, is the count of different websites cited inside stored records (court PDFs, company sites), which are citations rather than APIs.

Did earlier versions show more?

Sometimes, for four reasons. Some modules used to show broad news searches on their own names (tens of unrelated articles) and were switched to proper registers in September. Filters added this month show only what the module is about (Cabinet). The 4-second limit added this week means slow sources now show their stored copy instead of waiting. And the backup Excel files, which are much larger (14,123 constituencies, 4,104 MLAs, 43,547 Supreme Court and 661,267 High Court judgments), were shown on the local copy but only reached the live site this week.

Problems that cut across desks

  1. All 82 MB of backup files are on the live server, not just the four I listed

    My earlier statement was wrong: Vercel packages every file the backup reader can open, so the four-file list has no effect. Since this week's change the live site uses them all. Some fill modules with the wrong kind of data: Box Office falls back to news headlines, OTT to a TV schedule, and the unbuilt Sports Governance module shows month-old headlines. Counts also swing, for example Satellite Infrastructure between 12 launches and 500 catalogue rows.

    Fix: exclude the backup folder from the server except the files chosen by name, and use a backup only when it holds the same kind of record as the module.

  2. Ten modules flip between live, stored and empty from one request to the next

    Their sources take a little over 4 seconds (Wikidata, Manifold, Box Office, Athlete Index, District Performance). Between two passes, Prediction Markets went 31 → 250 rows and Celebrity Index 246 → 0. Geopolitics News Wire is stuck a month old because it waits on GDELT, which refuses us, before trying BBC.

    Fix now: speed up each source (run Manifold's three calls together, try BBC first, give GDELT a 2-second limit or drop it, keep Wikidata answers stored). Fix for good: scheduled fetching (F160).

  3. Four live sources are broken

    PIB now redirects its English feed to Hindi, so AI & Tech shows nothing (Cabinet and Policy Pipeline use the same feed). Wikidata times out on the Top Financial & Business Players query, which has no stored copy. Morning Brief and Statement Tracker call a route that does not exist on the live site (F166) and their sources take 11 to 43 seconds.

    Fix: add &reg=3 to the PIB address, rewrite the Wikidata query, and switch the two brief pages to the server's existing module route.

  4. Several modules are thin by configuration, not by source

    ISL Tracker asks ESPN for today's matches only, hence 1 row; asking for the season returns 154. Regulatory Body Watch stops at the first feed that answers (RBI, 10 rows) and never reads RBI press releases or SEBI, so 121 stored rows stay hidden. Global Exchanges has 5 symbols. Wikidata lists stop at 500 (of 4,100 MLAs and 822 districts).

    Fix: small changes per module, listed in the table below.

  5. Stored data is old and the larger datasets were never loaded

    Supreme Court orders run to 2 July, NCLT and IBBI to 8 August, Central Tenders still marks July deadlines as Open, budget figures are 2025-26, NSE quotes are frozen at 15 July without showing that date, and most Global registers date from 2025 to September 2026. The big all-India and court datasets in the backup files have never been loaded as proper stored copies with their dates shown.

    Fix: load the registers that matter as dated stored copies, show "as of" dates on every stored module, and move them onto scheduled refresh.

  6. The status labels overstate what is live

    The source registry says "Direct feed configured" for every entry, and several notes promise live connections that do not exist (Energy "swaps to EIA/Trading Economics live"). The admin screen inherits this.

    Fix: make the admin screen show what pages actually receive (live or stored, rows, newest date, reason), and later read F160's run log instead of a second health screen.

A suggested order, for when we decide what's next

  1. Quick fixes, a day or two: the backup files (problem 1), the PIB address, ISL season, Regulatory Watch's other feeds, Geopolitics source order, Manifold in parallel, Morning Brief and Statements (F166), plus F167 and F168.
  2. Honest status: the admin screen and registry labels show real status, and stored modules show their "as of" date.
  3. Data: load the 158 Cabinet decisions and the other large registers as dated stored copies.
  4. F160 scheduled fetching, with the timer every 5 minutes, which ends the flipping and keeps data fresh.
