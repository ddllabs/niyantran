## What it delivers

On a verdict card in the fact-check panel, the user can pay 100 credits (L26) to have that claim checked again. The
new result is shown first, with its date; the earlier result is kept and can be opened. It works while a session
runs and after it has ended, for the cards on screen. The user's own claims only, as everything in slice 1.

A view of past sessions is not part of slice 1, so a claim can be re-checked only while its card is in the panel.

## Fixed interfaces

### Flag

The `livetv_factcheck` flag row gains an optional number, `recheck_credits`. Re-check is available only when the
flag is on and `recheck_credits` is a number above 0 and at most 1,000. Absent or malformed: re-check is off and
nothing else changes. At release the row carries `recheck_credits: 100`.

### SQL (new migration `20261116110000_factcheck_recheck.sql`; nothing existing is replaced)

All `SECURITY DEFINER`, `search_path = ''`, executable by `service_role` only.

- `public.factcheck_recheck_begin(p_user uuid, p_claim uuid, p_is_admin boolean, p_expected_credits numeric)
  returns jsonb`
  Refuses with `{ok: false, reason}`: `off` (flag off or no re-check price); `not_allowed` (audience is admin and
  `p_is_admin` is false); `not_found` (no such claim of this user); `not_recheckable` (the claim's status is not
  `checked` or `error`, or it has already been superseded by a newer row); `price_changed` with `recheck_credits`
  (the price differs from `p_expected_credits`); `insufficient` with `needed` and `available` (available credits,
  counted as research chat counts them, are below the price); `rate_limited` (more than 6 re-checks begun by this
  user in the calendar minute); `in_progress` (this claim already has a re-check row still `pending` and younger
  than 90 seconds). Otherwise inserts a new claim row copying the session, user, video, position, spoken time,
  quote, claim text, claimant, reporter and kind, with `status = 'pending'` and `supersedes = p_claim`, and
  returns `{ok: true, claim_id, recheck_credits}`. It charges nothing.
- `public.factcheck_recheck_charge(p_user uuid, p_claim uuid) returns jsonb`
  Called once the new row holds a verdict. Idempotent per claim. Refuses unless the row is this user's, has
  `supersedes` set and `status = 'checked'`. Charges the price that was current at `begin` (stored on the row in a
  new nullable column `recheck_credits`) as a ledger `charge` with the note `live tv fact-check` under a private
  random key, drawn from lots like any charge, shortfall to debt. Returns `{ok: true, credits_charged, balance,
  repeated}`.

A re-check whose model call fails, or whose reply is not a usable verdict, is saved with `status = 'error'` and is
never charged.

The charge carries the same note as a session charge, so the usage reports of F347 list it as a
"Live TV fact-check" row with no session detail. No report function changes.

### Edge Function `factcheck`, new action

| Action | Request | Response |
|---|---|---|
| `recheck` | `claim_id`, `expected_recheck_credits` | `200 {claim: {id, supersedes, status, verdict, reason, sources, checked_at}, credits_charged, balance}`; `402 {reason: "insufficient", needed, available}`; `403 {reason: "off" or "not_allowed"}`; `404 {reason: "claim_not_found"}`; `409 {reason: "not_recheckable" or "price_changed", recheck_credits}`; `429 {reason: "rate_limited" or "in_progress"}` with `Retry-After` |

The common gate runs first (origin, token, active account). It does not call `factcheck_touch`: a re-check is not
part of a session's time or budget. The claim text comes from the database. The check is the same model call and
parsing as `check`, including the rule that a label without a source is an error except "No evidence found". The
charge is made only after a verdict is saved. A provider failure returns `502` and leaves the new row as `error`.

### Browser

- `src/lib/factcheck/client.js`: `recheck({claimId, expectedRecheckCredits})` with the status mapping above.
- `src/shell/factcheck/factCheckFlag.js`: reads `recheck_credits` (`null` when absent or out of range).
- Panel: on a card whose status is `checked` or `error`, a "Check again · 100 credits" button, shown only when the
  re-check price is known. It asks for confirmation with the price and the balance, shows progress, then puts the
  new result above the old one, which stays available under "Earlier result" with its date. Errors in plain words;
  a failed re-check says nothing was charged. Credits are refreshed after a charge. Works in the running and ended
  views. With no `recheck_credits` in the flag the panel is exactly as before.
