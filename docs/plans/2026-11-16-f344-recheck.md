## What it delivers

On a verdict card in the fact-check panel, the user can pay 100 credits (L26) to have that claim checked again. The
new result is shown first, with its date; the earlier result is kept and can be opened. It works while a session
runs and after it has ended, for the cards on screen. The user's own claims only, as everything in slice 1.

A view of past sessions is not part of slice 1, so a claim can be re-checked only while its card is in the panel.

## Fixed interfaces

### Flag

The `livetv_factcheck` flag row gains an optional number, `recheck_credits`. Re-check is available only when the
flag is on and `recheck_credits` is a number above 0 and at most 1,000. Absent or malformed: re-check is off and
nothing else changes. At release the row carries `recheck_credits: 100`.

### SQL (new migration `20261116110000_factcheck_recheck.sql`; nothing existing is replaced)

All `SECURITY DEFINER`, `search_path = ''`, executable by `service_role` only.

- `public.factcheck_recheck_begin(p_user uuid, p_claim uuid, p_is_admin boolean, p_expected_credits numeric)
  returns jsonb`
  Refuses with `{ok: false, reason}`: `off` (flag off or no re-check price); `not_allowed` (audience is admin and
  `p_is_admin` is false); `not_found` (no such claim of this user); `not_recheckable` (the claim is not `checked`, is a
  re-check row in `error`, or already has a newer `checked` row naming it; in that last case the answer also carries
  `newer_claim_id`); `price_changed` with `recheck_credits` (the price differs from `p_expected_credits`, or either is
  missing or invalid); `insufficient` with `needed` and `available` (available credits, counted as research chat
  counts them and less any re-check of this user that is begun and not yet charged, are below the price);
  `rate_limited` (more than 6 re-checks begun by this user in the calendar minute); `in_progress` (this claim already
  has a re-check row still `pending` and younger than 90 seconds); `too_many_failures` (10 or more failed re-checks by
  this user in 24 hours, or 3 or more on the same claim). An original claim in `error` can be re-checked, a failed
  re-check never blocks another attempt, and a re-check of a re-check is allowed through the newest successful row.
  Otherwise inserts a new claim row copying the session, user, video, position, spoken time, quote, claim text,
  claimant, reporter and kind, with `status = 'pending'` and `supersedes = p_claim`, and returns
  `{ok: true, claim_id, recheck_credits}`. It charges nothing for the new re-check, but it first charges any earlier
  re-check of this user that holds a verdict and was not yet charged, even when it then refuses.
- `public.factcheck_recheck_charge(p_user uuid, p_claim uuid) returns jsonb`
  Called once the new row holds a verdict. Idempotent per claim. Refuses unless the row is this user's, has
  `supersedes` set and `status = 'checked'`. Charges the price and the credit unit from a private record written at
  `begin`, never from the claim row's `recheck_credits` column, which is for display, as a ledger `charge` with the note
  `live tv fact-check` under a private random key, drawn from lots like any charge, shortfall to debt. Refusals are
  `not_found` and `not_chargeable`. Returns `{ok: true, credits_charged, balance, repeated}`.
- `public.factcheck_recheck_collect() returns int`
  Charges every checked, uncharged re-check for all users, marks re-check rows still `pending` after 5 minutes as
  `error`, and runs every 5 minutes under `pg_cron`. Executable by `service_role` only.

A row with no private record (for example one inserted by hand) can never be charged.

A re-check whose model call fails, or whose reply is not a usable verdict, is saved with `status = 'error'` and is
never charged.

The charge carries the same note as a session charge, so the usage reports of F347 list it as a
"Live TV fact-check" row with no session detail. No report function changes.

### Edge Function `factcheck`, new action

| Action | Request | Response |
|---|---|---|
| `recheck` | `claim_id`, `expected_recheck_credits` | `200 {claim: {id, supersedes, status, verdict, reason, sources, checked_at}, credits_charged, balance, charge_pending}`; a saved `error` claim returns `credits_charged: 0`; a verdict whose charge is delayed returns `credits_charged: null` with `charge_pending: true`; `400` for invalid input; `402 {reason: "insufficient", needed, available}`; `403 {reason: "off" or "not_allowed"}`; `404 {reason: "claim_not_found"}`; `409 {reason: "not_recheckable"}`, which may carry `claim` (the newer result) and carries no price; `409 {reason: "price_changed", recheck_credits}`; `429 {reason: "rate_limited" or "in_progress"}` with `Retry-After`; `429 {reason: "too_many_failures"}` without `Retry-After`; `503` when credit writes are paused or the provider key is missing |

The common gate runs first (origin, token, active account). It does not call `factcheck_touch`: a re-check is not
part of a session's time or budget. The claim text comes from the database. The check is the same model call and
parsing as `check`, including the rule that a label without a source is an error except "No evidence found". The
charge is made only after a verdict is saved. A started re-check finishes on the server even if the browser
disconnects, and is charged. A provider failure returns `502` and leaves the new row as `error`, uncharged.

### Browser

- `src/lib/factcheck/client.js`: `recheck({claimId, expectedRecheckCredits})` with the status mapping above.
- `src/shell/factcheck/factCheckFlag.js`: reads `recheck_credits` (`null` when absent or out of range).
- Panel: on a card whose status is `checked` or `error`, a "Check again · 100 credits" button, shown only when the
  re-check price is known. It asks for confirmation with the price and the balance, shows progress, then puts the
  new result above the old one, which stays available under "Earlier result" with its date. Errors in plain words;
  a failed re-check says nothing was charged; an answer that did not arrive says the check may have finished and been
  charged, and pressing the button again shows that result; a result that arrives after the panel was reset is
  announced with its charge. Credits are refreshed after a charge. Works in the running and ended views. With no
  `recheck_credits` in the flag the panel is exactly as before. `too_many_failures` hides the button for that card.

- **R1. Database** — `supabase/migrations/20261116110000_factcheck_recheck.sql`, `supabase/tests/factcheck_recheck.sql`,

- **R2. Edge Function** — `supabase/functions/factcheck/**`. Deno tests for the gate, each mapping, the charge
  only after a saved verdict, no charge on provider failure or unusable reply, the stored claim text being used,
  logging. Whole-tree `deno test`, lint, fmt.
- **R3. Browser** — `src/lib/factcheck/client.js`, `src/shell/factcheck/**` and tests. `npm test`, lint, build,
  bundle check.
- **R4. Review** — one Opus review across R1 to R3, then fixes. Reviewed 2026-11-16, accept with required fixes:
  re-checks in flight were not counted against the balance (six parallel re-checks took a user from 148 credits to
  minus 452 in the reviewer's run), failed attempts could call the provider without limit and without charge, and
  three cases could charge the user without showing the result. Fixes in progress.
