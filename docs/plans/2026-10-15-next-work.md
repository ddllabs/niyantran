## Part C — step 5: store every item, refreshed on a schedule

**Design** (approved records-first, F170 rules 1–3, replacing F160's one-snapshot-per-module table):

- **`feed_items`**: one row per listed item, kept and updated in place.
  - Key: `tier`, `feature`, `item_key`. The item key is the corpus identity where the corpus holds
    the document (for example `bill:2025:113`), else the item's link, else a hash of its title and
    date.
  - Also holds: the row as served, title, link, published date, first seen, last seen, and kind.
  - Kinds: official, news, measurement, live state.
- **`feed_daily`**: one summary row a day for measurement modules.
- **`feed_state`**: one row per module: schedule, lease, failures, last error, last fetched, the
  answer's notes and links, and a `serve` switch.
- **`feed_runs`**: one row per attempt, kept 30 days.
- **Retention**, in a daily `pg_cron` job:
  - official records forever;
  - news kept as headline, link, date and excerpt;
  - measurement detail 30 days, plus the daily summary;
  - live state latest only;
  - run logs 30 days.
- **The timer**: `pg_cron` every 5 minutes (owner decision) calls `POST /api/feeds/refresh` on Vercel
  through `pg_net`. The secret lives in Vault and in Vercel (production only), checked timing-safely.
  The route runs whatever modules are due, within 55 s. How often each class is due:

  | Class | Every |
  |---|---|
  | News | 30 min |
  | Markets | 15 min |
  | Official feeds | 60 min |
  | Reference data | daily |
  | Statement Tracker leaders | 6 h |

- **Serving**:
  - `/api/feature-feed` and the landing summaries read a scheduled module's items from the database:
    newest first, paged like Bills, labelled "Updated N min ago".
  - If the database has nothing yet, or does not answer, today's live path is used.
  - Pages stop waiting on outside sources, so the cold-start misses (Athlete Index, Box Office, MLA
    Report Card on first request) end.
- **Your registers**, loaded once: Cabinet's 158 decisions first, then 4,104 MLAs and 14,123
  constituencies. Court judgment sets follow, because of their size.
- **No chunking, OCR or full-text fetching.** Drag-to-chat is unchanged. Items stay separate from
  `desk_rows`, the AI's citable records; making new items citable in chat is a later, separate
  decision.
