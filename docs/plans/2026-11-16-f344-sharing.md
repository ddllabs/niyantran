## Gates

- **G-live: not passed.** No real session has run. The owner instructed on 2026-11-16 to finish the build and

  until the flag row carries `share_recorded: true`, and that key is set only after the owner's first live session.

## Decisions taken for the build (supervisor's, for the owner to confirm at the check)

1. A shared stretch is one session's run over a recorded video. Two users' runs of the same part of a video are
   two stretches, newest first; nothing is merged. A stretch is unlocked as a whole.
2. A stretch is shared as soon as its session is settled. There is no waiting period.
3. Unlock price: `unlock_credits_per_minute` (100, L25) for each started minute of stored speech in the stretch.
   The user who ran the stretch pays nothing to read it and receives nothing when others unlock it.
4. A reported verdict is marked "reported" for everyone. Removal is by a platform admin through SQL
   (`factcheck_claim_hide`); there is no admin screen in this slice.
5. Stored transcripts are kept until removed. Removal for a whole video is by a platform admin through SQL
   (`factcheck_video_remove`).
6. Only a video the server can confirm is shared. The Edge Function asks the app's own server
   (`GET <LIVETV_API_BASE>/api/livetv/videos?channelId=<slug>`, the YouTube uploads list of ADR 0009, no
   `search.list`) and requires the video id in `recentVideos` with `isLive` and `isUpcoming` false. Anything else,
   including any failure of that request, leaves the session private exactly as in slice 1.
7. Positions come from the player in the user's browser and are checked for sanity, not proven. A user can still
   play other sound into the shared tab or misreport a position. Server-held text removes typed forgeries only;
   the report link covers the rest. This is the residual risk of ADR 0015 and the audit's L1.

## Fixed interfaces

### Flag

The `livetv_factcheck` row gains two optional keys. Sharing is on only when `share_recorded` is exactly `true` and
`unlock_credits_per_minute` is a number above 0 and at most 1,000. Otherwise every part of this slice is off and
slice 1 behaves exactly as before.

### SQL (new migration `20261117090000_factcheck_sharing.sql`; no existing function is replaced)

New columns: `factcheck_sessions.shareable boolean not null default false`;
`factcheck_claims.shared boolean not null default false`, `factcheck_claims.hidden_at timestamptz`.

New tables:

- `private.factcheck_pieces (session_id, user_id, video_id, piece_no int, pos_start_s numeric, pos_end_s numeric,
  text, created_at)`, primary key `(session_id, piece_no)`, cascade from the session. No API role reads it.
- `public.factcheck_unlocks (id, user_id, session_id, video_id, credits_charged, created_at)`, unique
  `(user_id, session_id)`; row-level security: a user selects own rows; written only by the server.
- `public.factcheck_reports (id, claim_id, user_id, reason, created_at, handled_at)`, unique `(claim_id, user_id)`;
  a user selects own rows; written only by the server.

Functions, all `SECURITY DEFINER`, `search_path = ''`, executable by `service_role` only unless stated:

- `private.factcheck_share_flag() returns jsonb`: `{audience, unlock_cpm}` or null when sharing is off.
- `public.factcheck_mark_shareable(p_user uuid, p_session uuid) returns jsonb`: sets `shareable` on the caller's
  active recorded session when sharing is on. Refusals `off`, `not_found`, `not_recorded`.
- `public.factcheck_piece_store(p_user uuid, p_session uuid, p_piece_no int, p_pos_start_s numeric,
  p_pos_end_s numeric, p_text text) returns jsonb`: stores one piece of an active, shareable session of this user.
  Refusals: `not_found`, `not_shareable`, `settled`, `bad_piece` (number below 1 or already stored; length not
  between 0.5 and 15 s; start earlier than the nearest lower-numbered piece's start, or more than 2 s before its
  end; end more than 2 s after the nearest higher-numbered piece's start; text empty or over 2,000 characters;
  more than 120 pieces in the session). Pieces may arrive out of order and a forward jump is accepted as a gap.
  A refused piece is not stored and the session goes on; nothing else changes.
- `public.factcheck_turn_pieces(p_user uuid, p_session uuid, p_from int, p_to int) returns jsonb`: the stored pieces
  of that range in order (at most 12 pieces), each `{piece_no, pos_start_s, pos_end_s, text}`; refusals
  `not_found`, `bad_range`.
- `public.factcheck_video_view(p_user uuid, p_video_id text, p_is_admin boolean) returns jsonb`: `{ok: true,
  unlock_credits_per_minute, stretches: [...]}` or `{ok: false, reason: 'off' | 'not_allowed'}`. Each stretch is one
  settled shareable session with at least one stored piece: `{stretch_id, from_s, to_s, minutes, checked_on,
  claims_count, access: 'own' | 'unlocked' | 'locked', price}` and, when access is not `locked`, `lines`
  (`{pos_start_s, text}` in order) and `claims` (id, position_s, quote, claim_en, claimant, reported_by, kind,
  status, verdict, reason, sources, checked_at, reported, and for a re-checked claim only the newest result). Only
  claims with `shared = true` and `hidden_at` null are returned. It never returns a user id, and `stretch_id` is the
  only identifier of the run. `minutes` is the stored speech in whole started minutes; `price` is
  `minutes × unlock_credits_per_minute`. At most 50 stretches, newest first.
- `public.factcheck_unlock(p_user uuid, p_stretch uuid, p_is_admin boolean, p_expected_credits numeric)
  returns jsonb`: charges the stretch's price through the ledger (a `charge` with the note `live tv fact-check`
  under a private random key, drawn from lots like any charge) and records the unlock, in one transaction.
  Idempotent: a second call returns `{ok: true, repeated: true}` and charges nothing. Refusals: `off`,
  `not_allowed`, `not_found`, `own` (the caller ran it), `price_changed` with `price`, `insufficient` with `needed`
  and `available` (counted as research chat counts them). Rate limit 6 a minute per user (`rate_limited`).
- `public.factcheck_report(p_user uuid, p_claim uuid, p_reason text) returns jsonb`: the caller can report a claim
  they can read (own, or of a stretch they unlocked). Refusals `off`, `not_found`, `already`, `rate_limited`
  (10 a day per user). Reason up to 300 characters, may be empty.
- `public.factcheck_claim_hide(p_claim uuid)` and `public.factcheck_video_remove(p_video_id text)`: only for a
  caller for whom `public.is_platform_admin()` is true (executable by `authenticated`, checked inside). The first
  sets `hidden_at` and marks the claim's reports handled; the second deletes the stored pieces of that video and
  clears `shareable` on its sessions.

A claim is `shared` only when it was extracted from stored pieces of a shareable session (the Edge Function sets it
through the insert it already does; the column default keeps every slice 1 claim private).

Fixture `supabase/tests/factcheck_sharing.sql` and a chain entry in `supabase/tests/run.sh`, with the vacuity check.
The audit's forged-quote case is a regression test: a claim inserted from browser text is never returned by
`factcheck_video_view` to another user.

### Edge Function `factcheck`

- `start`: unchanged request. When sharing is on and `video_kind` is `recorded`, after a successful
  `factcheck_start` it confirms the video (decision 6, 4 s timeout) and on success calls `factcheck_mark_shareable`.
  The response gains `shareable: boolean`. A failed confirmation never fails the start.
- `transcribe`: optional fields `piece_no`, `pos_start_s`, `pos_end_s`. When all three are present and the text is
  not empty, it calls `factcheck_piece_store` after transcription. The response gains `stored: boolean`. A refusal
  is not an error.
- `extract`: `turn` may carry `piece_from` and `piece_to` instead of `text`. The server then builds the turn text
  from the stored pieces with the overlap clean-up (a TypeScript port of `mergeOverlap` and `stripSoundTags` from
  `src/lib/factcheck/pieces.js`, proven equal on one shared fixture file that both test suites read), takes
  `position_s` from the first piece, and saves the claims with `shared = true`. `recent` is still sent by the
  browser and is context only. With `text`, behaviour is exactly as today and claims are not shared.
- New actions: `video_view {video_id}`; `unlock {stretch_id, expected_credits}` (402 `insufficient`, 409
  `price_changed`, 409 `own`, 429 `rate_limited`, 404, 403 `off`/`not_allowed`); `report {claim_id, reason}`
  (409 `already`, 429, 404, 403). None of them calls `factcheck_touch`; all pass the common gate.
- New environment name `LIVETV_API_BASE` (the app's public origin; not a secret). Missing: nothing is shareable.

### Browser

- `src/lib/factcheck/client.js`: `videoView`, `unlock`, `report`; `transcribe` and `extract` pass the new fields.
- `src/lib/factcheck/session.js`: when `start` answers `shareable: true` and a position getter is given, each piece
  is sent with its number and the player's position at its first and last sample; a turn is sent as a piece range.
  A piece cut while the player is paused, buffering or seeking (position not advancing with the audio) is sent
  without position fields, and a turn containing such a piece is sent as text.
- `src/shell/factcheck/factCheckFlag.js`: reads the two new keys.
- Panel, on a recorded video when sharing is on: a "Checked parts of this video" list (position range, minutes,
  date, number of claims). The user's own and unlocked parts open to the transcript lines and verdict cards with
  their check dates. A locked part shows its price and the balance, and unlocks after confirmation. Each shared
  card has "Report this verdict". Starting a block while a locked or open part covers the current position offers
  that part first. Plain words throughout; with sharing off the panel is exactly as before.

## Changes from the reviews (2026-11-16)

One correctness review, one security audit and a second security pass; all findings applied.

- A shared claim is built only from text the server holds. On a turn sent as a piece range the browser's `recent`,
  ledger and seed are ignored: context is the stored pieces before the range, the seed is the session's channel,
  and a claim whose quote is not in the turn text is dropped. A turn sent as text can neither create nor change a
  shared claim (the audit's two high findings).
- `start` asks `public.factcheck_share_on(p_is_admin)` first and confirms the video only when sharing is on. The
  app server's videos answer carries `dataOrigin`, kept through its cache; only `youtube-api` is accepted.
- A piece is stored only when its declared length is within 1.5 s of the audio sent. The browser corrects the
  player's position by the audio the cutter still holds. Playback at a speed other than 1x is never stored.
- `minutes` and `price` count speech once where pieces overlap, and gaps are not billed.
- A stretch is listed for others, and can be unlocked, 2 minutes after its session ended, because a session accepts
  late extraction and checks for that long. The runner sees it at once.
- A viewer who unlocked a stretch sees each claim's original result; a later re-check by the runner is shown to
  the runner only. Cards inside a listed part have no "Check again" in this slice.
- `factcheck_video_view` is limited to 30 calls a minute per user and lists at most the 3 newest stretches of one
  runner, plus the viewer's own and unlocked ones; `checked_on` is a date.
- "Reported" shows only while an unhandled report exists; `public.factcheck_report_dismiss(p_claim)` (platform
  admin) clears it.
- Deleting a runner's account or session removes its pieces and other users' unlock rows for it; their charges
  stay and nothing is refunded.
- Before starting a block on a shareable video the panel says that other users will be able to pay to see it.
- The function reads the `shared` column, so the migration is applied before the function is deployed.

Known limits, accepted: positions come from the user's browser and audio from the user's tab (decision 7); all
claims of one turn carry the position of the turn's first piece.

## Not in this plan

Re-analyzing a block; a view of past sessions; an admin screen for reports; sharing of live-stream results.
