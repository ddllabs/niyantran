## Problems, verified

1. **Search folding differs between the client and the database.** This was checked on a local
   PostgreSQL 17 with `en_US.utf8`:
   - `\s` in a PostgreSQL pattern does not match a no-break space (U+00A0) or an em space (U+2003).
     JavaScript's `\s` matches both.
   - The client applies NFC to the query and to the PDF's text; the database applies nothing. NFC
     rewrites क़ (U+0958) as क + ◌़ (U+0915 U+093C), so stored text holding U+0958 is never found.

   Either way, a page can show a match that the database never lists, or the reverse.
   (`lower()` folds É correctly under this locale.)
2. **A failed thumbnail closes the part it shares with page renders**, so pages being drawn from
   that part fail and the PDF error banner can show.
   - pdf.js keeps every page it has drawn in memory (`page.cleanup()` is never called), so a long
     single-part document grows as the reader moves through it.
3. **Safari has no scroll anchoring** (`overflow-anchor`). In the continuous Text view, a batch read
   above the reader replaces the 520 px place holders with real text, and the reader's place moves.
4. **Highlight names are global, but each viewer keeps its own registry.**
   - `dispose()` deletes the name, so two viewers mounted at once would clear each other's marks.
   - This is safe today with one viewer, but fragile.
5. **Smaller items:**
   - the rail's tabs lack Home and End;
   - the search result is not cleared when the document's extraction changes while search is open.

The F50 item about the stored column's table rewrite was settled when migration 42 was applied (34
rows, recorded), and needs no change.

## Expected outcome

1. **Migration 43** folds `search_text` and the query alike:
   - NFC first;
   - then every Unicode space that JavaScript's `\s` matches, plus the Markdown marks (`#*_|`` ` ``),
     as one space.

   It uses `ALTER COLUMN … SET EXPRESSION` (PostgreSQL 17) and `create or replace` on the function.
   The signature, grants and security settings are unchanged.
2. **The pool:**
   - closes a part only when the part itself fails (its transport or its document). A page or
     thumbnail that fails alone fails only its own job.
   - calls `pdfPage.cleanup()` after each draw.
3. **Where the browser has no `overflow-anchor`**, the continuous Text view keeps the reader's place
   itself: the page under the top of the view, and how far into it the reader is, stay put when
   batches arrive.
4. **One shared registry per highlight name.** A viewer's `dispose` removes only its own ranges.
5. **Home and End on the rail tabs,** and the search result cleared when the extraction changes.

## Acceptance evidence

1. **The SQL fixture** gains cases for a no-break space, an em space, क़ written either way, and É.
   They fail on migration 42 and pass on 43. The whole fixture and its vacuity check pass, and
   `npm run test:sql` passes.
2. **Pool tests:** a failed thumbnail on a shared part leaves page renders on it running; `cleanup` is
   called after a draw. Each fails first.
3. **A test with a fake region:** when a batch above the view grows, the reader's place is kept.
   The harness is checked with anchoring forced off (`overflow-anchor: none`).
4. **Highlight tests:** two highlighters on one name keep each other's ranges, and disposing one
   leaves the other's.
5. **Markup and hook tests** for Home, End and the reset.

Lint, both suites, the SQL fixtures and the build pass. The viewer chunk stays within piece 2's
remaining budget, 3.4 kB gzip.
