## Behavior and acceptance contract

### A. Feed reliability (F160, F215)

1. **Empty nothing-new runs.** Only a store with retained items may use the
   existing kept-items `unchanged` branch. An initial empty response must not
   advance item freshness as though retained content exists. Only a proven
   successful source check may reset source-failure counts; a mere flag on an
   unreadable answer cannot. Distinguish a successfully checked, genuinely empty
   source in diagnostic evidence and keep its store availability empty; do not
   fabricate records or treat inability to read as no change.
   Preserve the existing run-status vocabulary unless evidence requires a
   separately reviewed interface change.
2. **Queue cancellation.** A caller abort releases its host wait promptly,
   before acquiring a network slot. An expired request never invokes the
   upstream fetch. Queue accounting, host serialization, sibling requests,
   module deadlines and the refresh's hard budget remain correct. Apple and
   iTunes fallback stay within the existing budgets; do not raise timeouts.
3. **Constitution identity.** Successive unchanged constitutions retain keys
   despite response order, display changes and fetch time. Distinct versions
   stay distinct. Establish identity from repeat samples before choosing the
   rule; inventory affected stored keys before any production replacement.
4. **Latest-run reads.** Retrieve only the current successful run for modules
   whose display contract is latest-run-only, with bounded pagination and
   consistent run identity across pages. Test more than 2,000 items and a
   refresh between reads. Never return a silent partial list. Reuse existing
   RPCs if adequate; otherwise introduce a service-role-only reader. Separate
   this read problem from the per-refresh ingestion batch cap; do not silently
   increase that cap. Stock exchanges retain their intentionally different
   last-known-value behavior.
5. **World fixtures.** Determine whether failures are HTTP refusal, exhausted
   budget, incompatible JSON or an actually empty schedule. Preserve Premier
   League, NBA, IPL and La Liga coverage, dates and event identity. Record
   per-league completeness so partial success cannot conceal a missing league.
   Prefer repairing the existing adapter. A paid replacement, redistribution
   uncertainty or reduced coverage requires the owner's concrete decision.
   News headlines are not fixture data.

### B. MLA Profiles reliability (F160; scorecard remains M3)

Serve the existing profiles as reference data, using stable profile identity
and honest sample/coverage labels. Preserve the module's canonical ID and its
"Profiles & Coverage" presentation. Keep coverage news separate from reference
profiles using distinct typed rows/section tags and source identities in the reference
snapshot and presentation; do not turn an unfiltered news wire into
a directory. A repeat read must survive Wikidata being slow or unavailable
using a usable stored reference copy. Missing states and incomplete coverage
are visible. Do not claim attendance, performance scores or affidavit coverage.

Reference data may use a timer-backed reference refresh or the existing register
loader: choose the simpler supported path after measuring the source. A fixed
register load is a separate production action, not implied by source changes.

### C. Handbook correctness (F201 optional findings, now included)

- An explicitly selected year returns that year's figures only. Missing
  indicators/states show an explicit gap; another year is never substituted.
  With no year selected, latest available is allowed and labelled per indicator.
- The previous comparison is the immediately preceding comparable calendar or
  financial period. If absent, omit year-on-year change and state that the
  previous period is unavailable. An older observation may be shown separately
  only with its actual year, never as a year-on-year change.
- Stored and source-page paths produce equivalent results for these rules,
  including missing indicators and gaps across block boundaries. Load enough
  block metadata/records to establish the result without fetching every table.
- Whole-variant reads ask for page one and only the remaining necessary pages;
  complete-result and concurrent-reload checks remain intact.
- Preserve calendar-year, financial-year and multi-year survey semantics.
  Prefer explicit `year`/`period` and period-aware filtering over changing a
  shared date helper globally. A range matches a period when their intervals
  overlap, with the period shown as written; an exact year/period filter is
  exact. Calendar 2019 spans 1 January–31 December 2019; financial 2019-20
  spans 1 April 2019–31 March 2020; a survey span 2019-21 spans the stated
  calendar years inclusively unless source metadata supplies narrower dates.
  Label that year precision rather than inventing collection dates. Test these
  three forms and their boundaries.
  Unrelated module date behavior must not change. Any necessary handbook-only
  desk-row reload needs an exact inventory and separate production approval.

### D. Research grounding and thread evidence (F216, F210)

Caveats, gaps and qualifications are factual claims too. "Provisional",
"estimated", "incomplete" and revision claims require returned evidence.
Otherwise say the qualification is unknown. Preserve qualifications the source
does supply. No fabricated caveat may be justified merely as an inference.
Test supporting and missing evidence; a prompt-string test alone does not
prove generated-answer behavior. Any paid behavioral evaluation requires its
own authorized budget and must not write to production chats.

Thread tests synchronize on the send, persistence/reconciliation and request
type. Verify same-account re-announcements preserve sends and answers while
cross-account changes/sign-out still reject. Reproduce the scheduling failure
with controlled delays. Do not add retries, longer sleeps, skipped tests or
weaker ownership assertions to obtain green runs.

### E. Stored search cleanup (F202)

Inventory every proposed removal by file, entry ID, field, old value/hash,
consumer and reason. Scope is `src/data/source-registry.json` and
`src/data/html-feature-map.json` only. Prove routing and provenance do not use
each removed value. Preserve canonical IDs, rows, source links still in use,
route markers and module coverage. No blanket URL deletion. Store the exact
inventory as a dated research record before editing data files.

### F. Frontend leftovers (M2: F208, F202)

- Keep the public module identity/count contract lightweight. Load column
  schemas and full feature configuration with the terminal, preserving all
  120 catalogue identities, search behavior (including field-label queries),
  planned status, summaries and module navigation. Preserve build-script
  consumers and the generated desk-module contract.
- Measure initial assets before/after on the same toolchain. Both entry gzip
  and the total JavaScript fetched before entering the terminal must decrease;
  shifting bytes to an eagerly preloaded chunk is not success. Lower the bundle
  baseline only after this is established. Keep existing tolerance, stylesheet,
  geography-pack and PDF lazy-load guards.
- The leader panel shows the selected row's real Wikidata item link through

  a specific person. Missing/unsafe links show no invented source; accessible
  labels and safe external-link handling are required. Existing as-of and
  stored-register language stay intact.
